01 / The brief

A small tool for a very specific release-day problem.

README.md / WHY_GHOSTTESTER

# target_user

For teams shipping complex 3D spaces.

Indie developers protecting their sanity during a tight release schedule, plus AA/AAA QA teams that need more coverage than human wall-walking can provide.

// Not a general-purpose test suite.
// A focused collision signal for game teams.

# pain_point

Manual coverage misses the weird stuff.

A tester can spend hundreds of hours walking into walls, but cannot recreate every jump, crouch, wall-hug, and high-velocity edge case. One missed breach becomes a Day-1 crash or a costly post-launch patch.

issue_status: unresolved_without_automation

02 / The AI core

A build pipeline for collision evidence.

No magic box. Three observable stages from movement data to a ticket your team can triage.

01 / CAPTURE_coordinates

Autonomous Exploration

A lightweight reinforcement learning agent roams Unity or Unreal maps, recreating chaotic player behavior across jump, crouch, and wall-hug paths.

02 / DETECT[breach_event]

Instant Collision Breach

When transform coordinates cross a solid mesh layer, the engine pauses, captures the physics state, and preserves the exact failing frame.

03 / REPORT-> git_issue

LLM Reasoning & Reporting

Telemetry and a frame snapshot become a structured report with severity, coordinates, collider context, and a production-ready JIRA ticket.

Honest limitations

Minor false positives can occur on non-solid visual meshes such as foliage or cloth curtains. The active bounding-box metadata filter bypasses non-blocking layers.

Zero security risks

The SDK operates locally inside engine telemetry. Only lightweight text strings, coordinates, and object names are sent to the LLM API for report generation.
